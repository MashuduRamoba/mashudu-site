Why Power Automate is the Most Underrated Tool in Microsoft 365

Most companies have it. Almost none use it properly. After building production workflows at Landis+Gyr (now EYKON Utility Solutions) that saved hours of manual work weekly, here's my honest take on what Power Automate can really do in 2025.

MR
Mashudu Ramoba
IT Intern · Landis+Gyr EMEA · Power Automate Developer

Every company with a Microsoft 365 licence has Power Automate. It comes included — no extra cost, no installation required. And yet in most organisations, it sits completely unused while staff spend hours every week on tasks a well-designed flow could handle in seconds.

I built production Power Automate workflows at Landis+Gyr (now EYKON Utility Solutions) (now EYKON Utility Solutions) (now EYKON Utility Solutions) as part of my role. Watching those flows run for the first time — routing documents, sending notifications, updating records automatically — was genuinely exciting. Here's what I learned about what Power Automate can actually do and why it deserves more attention.

What Is Power Automate?

Power Automate (previously called Microsoft Flow) is a no-code / low-code automation platform built into Microsoft 365. It lets you create automated workflows — called flows — that connect apps and services, respond to events, and perform actions without any human involvement.

Think of it as a programmable connector between every Microsoft tool — SharePoint, Teams, Outlook, Dynamics 365, Excel, Forms — and hundreds of external services like Salesforce, Slack, Twitter, and Google Workspace.

The Three Types of Flows

  • Automated flows — triggered by an event. "When a file is uploaded to this SharePoint library, send an approval email."
  • Scheduled flows — triggered on a timer. "Every Monday at 08:00, generate a report and email it to the team."
  • Instant flows — triggered manually by a button click, from Teams, SharePoint, or the mobile app.

Real Workflows I Built at EYKON / Landis+Gyr EMEA

Here are three actual flows I designed and deployed during my internship:

Document Approval
Automated Document Approval Routing

Problem: Client service documents were being emailed back and forth for approval — no audit trail, frequent delays, version confusion.
Flow: When a document is uploaded to a specific SharePoint library → send approval request to manager via Teams → if approved, move to "Approved" folder and notify the requester → if rejected, notify with comments → log all decisions to a SharePoint list for audit.

Notification
New Client Account Alert

Problem: When new accounts were added to Dynamics 365, relevant team members only found out hours later during manual check-ins.
Flow: When a new account record is created in Dynamics 365 → extract key fields → post a formatted notification card to the relevant Teams channel in real time.

Scheduled Report
Weekly Status Report Automation

Problem: A team member spent 45 minutes every Friday manually compiling a status report from a SharePoint list into an email.
Flow: Every Friday at 16:00 → query the SharePoint list → format the data into an HTML table → send a formatted email to the distribution list automatically.

Why Companies Underuse It

In my experience, there are three main reasons Power Automate sits unused:

  1. Nobody knows it exists. It's buried in the M365 app launcher and never gets introduced during onboarding.
  2. IT teams don't have time to build flows for every department. The value comes from empowering non-technical staff to build their own — but most companies don't provide training.
  3. Fear of breaking things. People worry that automating a process will cause errors. This is solvable with proper testing in a dev environment first.
✅ Where to Start

Find the most repetitive manual task in your team — something someone does the same way every week. That's your first automation candidate. Start simple: one trigger, one or two actions. Build confidence before tackling complex multi-step approval flows.

Power Automate vs Writing Code

As a developer, I sometimes get asked: "Why not just write a script?" Fair question. Here's how I think about it:

  • Use Power Automate when the workflow involves Microsoft 365 services, needs to be maintained by non-developers, or needs to be built quickly.
  • Write code when you need complex logic, high-volume data processing, or integrations that Power Automate connectors don't support well.
  • Combine both — Power Automate can call Azure Functions or custom APIs, so you can trigger custom code from a no-code flow. Best of both worlds.

The 2025 Outlook

Microsoft has been investing heavily in Power Automate. The 2025 additions that matter most:

  • Copilot in Power Automate — describe what you want in plain English, Copilot generates the flow. Dramatically lowers the barrier to entry.
  • Desktop flows — automate tasks on your Windows desktop, not just cloud services. Think: automating a legacy application that has no API.
  • Process Mining — analyse your existing processes to identify automation opportunities automatically.
⚠️ One Thing to Watch

Power Automate flows run under the account of whoever created them. If that person leaves the company, flows stop working. Always use a service account for production flows — a shared account that doesn't belong to one individual.

KEY TAKEAWAYS

  • Power Automate comes free with every M365 licence — most companies never use it properly
  • Three flow types: Automated (event-driven), Scheduled (timer), Instant (manual trigger)
  • Start with your team's most repetitive manual task
  • Use a service account for production flows — not your personal account
  • Copilot integration in 2025 makes building flows faster than ever

Power Automate is one of the highest-ROI skills you can develop as an IT professional in a Microsoft shop. The investment is low — a few hours to learn — and the impact is immediate and visible. If you want to stand out in an IT role, start automating things nobody else is automating.
