SharePoint Permissions Explained: A Practical Guide for IT Professionals

SharePoint permissions confuse a lot of people — even experienced IT teams. After spending months managing them at Landis+Gyr across EMEA, I broke down everything I learned into this practical guide.

MR
Mashudu Ramoba
IT Intern · Landis+Gyr EMEA · AZ-900 Certified

When I started my internship at Landis+Gyr, one of my first major responsibilities was managing SharePoint environments across EMEA. I quickly learned that SharePoint permissions are one of those things that everyone assumes they understand — until something breaks.

A user can't access a file they need. A team's documents are visible to the wrong people. A site collection suddenly has 47 permission levels and nobody knows why. Sound familiar? This guide explains how SharePoint permissions actually work, and how to manage them properly.

The Permission Hierarchy

SharePoint permissions work in a top-down hierarchy. Understanding this is the foundation of everything else.

  • Site Collection — the top level. Permissions set here apply everywhere below unless overridden.
  • Site (Subsite) — inherits from the site collection by default.
  • Library / List — inherits from the site by default.
  • Folder — inherits from the library by default.
  • Item / File — inherits from the folder by default.

The key word in every line above is "by default." You can break this inheritance at any level — and that's where things get complicated.

💡 Key Concept

When permissions flow down unchanged, it's called inheritance. When you set different permissions on a specific item or library, it's called breaking inheritance. Broken inheritance is the #1 cause of permission confusion.

The Three Default Permission Levels

  • Full Control — can do everything including delete the site and manage permissions. Site Collection Admins have this.
  • Edit / Contribute — can add, edit, and delete content. Most team members get this.
  • Read — can view content but not change anything. Good for stakeholders and external reviewers.

SharePoint Groups vs Direct Permissions

You can assign permissions to individual users or to SharePoint groups. Always use groups. Here's why:

  • When a new team member joins, you add them to the group — they instantly get the right access everywhere.
  • When someone leaves, you remove them from the group — access revoked everywhere at once.
  • Direct user permissions become impossible to audit as the site grows.
✅ Best Practice

Every site should have three groups minimum: [SiteName] Owners (Full Control), [SiteName] Members (Edit), and [SiteName] Visitors (Read). These are created automatically when you create a site — use them.

How I Used This at Landis+Gyr

At Landis+Gyr, we had SharePoint sites shared across multiple EMEA regions. The challenge was ensuring each regional team could access their own documents but not others', while certain cross-regional documents remained accessible to everyone.

  1. Created region-specific SharePoint groups (e.g., EMEA-North-Members, EMEA-South-Members)
  2. Set up separate document libraries per region
  3. Broke inheritance on each regional library and assigned only the relevant group
  4. Created a shared library that kept default site inheritance — accessible to all
  5. Documented every permission change in a change log for audit purposes

Checking Permissions on Any Item

1. Navigate to the file or library
2. Click the three dots (...) → Details
3. Click "Manage Access"
4. You'll see all groups and users with access
5. Click "Advanced" for full permission details
Connect-PnPOnline -Url "https://yourcompany.sharepoint.com/sites/yoursite" -UseWebLogin

# Get all unique permissions on a library
Get-PnPListPermissions -Identity "Documents" | Format-Table -AutoSize
⚠️ Watch Out For

Oversharing is the biggest SharePoint security risk. Check regularly that sensitive documents haven't been accidentally shared too broadly. Use the Access Review feature in SharePoint Admin Centre to automate this.

Quick Reference: Common Permission Tasks

  • Give someone access to one file: Right-click file → Share → enter email → set permission level
  • Remove all access for a user: Site Settings → Site Permissions → Find user → Remove
  • Make a library private: Library Settings → Permissions → Stop inheriting → Remove all → Add only who you want
  • Check who has Full Control: Site Settings → Site Permissions → filter by Full Control

KEY TAKEAWAYS

  • Permissions flow top-down — site collection → site → library → folder → file
  • Always use SharePoint groups, never direct user permissions
  • Breaking inheritance is powerful but creates complexity — document it
  • Audit permissions regularly using the built-in tools or PowerShell
  • Oversharing is the #1 SharePoint security risk — review access quarterly
